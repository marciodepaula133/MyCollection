- (decision) JWT validation: each service validates access JWTs itself (resolves SPEC open question). - (decision) Token lifetimes: access JWT 15 min; refresh token 30 days sliding (each refresh issues new one with fresh 30d). Resolves SPEC open question (lifetimes).
- (decision) Refresh tokens: opaque random, stored SHA-256 hashed in Auth Postgres table refresh_tokens (id, user_id, family_id, token_hash, expires_at, consumed_at, revoked_at). Rotate on every use; presenting a consumed token revokes the whole family. Logout revokes the family. Resolves SPEC open question (rotation).
- (decision) Token transport: refresh token ONLY in cookie refresh_token (HttpOnly; Secure; SameSite=Strict; Path=/api/auth), never in a body or URL. Access token only in JSON response body; frontend keeps it in memory and does silent refresh on boot. OAuth callbacks set cookie and 302 to frontend; frontend then calls /refresh-token. Gateway CORS: explicit origin allow-list with credentials, no wildcard. Prevents tokens in URLs/localStorage and per-flow token handoff divergence.
- (decision) Refresh reuse grace window: a consumed refresh token presented again within 10s of consumption returns the same successor instead of revoking the family (multi-tab race). After 10s reuse = theft -> revoke family.
- (decision) Non-browser clients (mobile/CLI) out of scope; future may add body-based refresh for them. Deferred.
